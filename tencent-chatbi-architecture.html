腾讯云 ChatBI 组件交互与分层部署架构图

组件名称均取自腾讯官方技术文章与产品手册的真实专属名称 · 按「应用层 / Agent 层（AI 中间处理）/ 大模型层 / 知识库层 / BI 引擎层 / 数据源层」六层展开 · Text2SQL 与 Text2DSL 为相互隔离的双通道 · 每个组件标注「● LLM / ● 知识库」使用徽标，总线 L / K 与流程序号一一对应

一、整体组件交互图（按部署位置分层）

数字编号 1~14 为主流程顺序；字母 L（紫色）为大模型调用总线、K（琥珀色）为知识库检索总线，具体哪些步骤经过 L / K 见下方图例与各组件右下角的「● LLM / ● 知识库」徽标。实线为主查询链路，虚线为回传/反馈链路。

1用户在各端输入自然语言提问，进入多轮对话模块（调用大模型 L 做历史语义补全，可结合习惯知识库）
2补全后的完整提问送入意图分类模块（调用大模型 L：无关拒识 / 时间主体完整 / 缺失三分类）
3缺时间或主体的问题进入意图澄清：先经 知识库总线 K（腾讯云 ES + 数据表知识库分词召回粗排），再经 大模型总线 L（LLM + 向量相似度打分精排）过滤不合理选项
4澄清选项按钮回传用户点选（选项必定来自知识库真实字段，虚线）；点选后回到步骤 5，不重走 1~3
5意图明确后进入智能选表：调用大模型 L 基于表名/表备注/字段备注（数据表知识库 K）做语义匹配，单表或多表关联
6简单查询分流 → Text2SQL 通道：调用大模型 L（结合计算字段/习惯知识/ICL 样本 K）直出 MySQL 方言 SQL
7复杂计算分流 → Text2DSL 通道：四个 Agent 各自调用大模型 L（结合 K）生成基本参数/维度/指标/条件区块；与步骤 6 互相隔离，二选一执行
8四个 Agent 的输出交由 DSL 整合与正确性验证合并、后处理（确定性工程代码，不调用大模型）
9Text2SQL 通道产物（MySQL SQL）送 BI 引擎的方言转换工具翻译为目标数据源方言（与步骤 10 互相隔离）
10Text2DSL 通道产物（完整 DSL JSON）送 BI 引擎的查询编译器按拖拽协议编译，复杂计算拆多条 SQL
11两条通道的编译结果统一经数据权限引擎注入项目隔离/行级权限后，物理 SQL 下发用户数据库执行（数据不离本地）
12查询结果返回 BI 引擎：结果缓存供图表切换不重算；智能工具在此基础上做统计归因（分布差异法 / XGBoost+SHAP），并调用大模型做维度推荐与总结、检索事件知识库
13图表 + SQL 白盒（展开推理）+ 结论渲染回应用层，支持二次交互
14点赞点踩反馈沉淀为 ICL Few-Shot 样本库（数据飞轮，服务步骤 6 / 7，虚线）
L大模型调用总线：步骤 1 / 2 / 3（精排）/ 5 / 6 / 7 及智能工具（数据解读、归因维度推荐与总结）经此调用大模型层；各组件右下角紫色「● LLM」徽标即表示经过 L 总线
K知识库检索总线：步骤 3（ES 粗排 · 数据表知识库）/ 5（表结构）/ 6 · 7（计算字段口径 · 习惯知识 · ICL 样本）及智能工具（事件知识库）经此检索知识库层；琥珀色「● 知识库」徽标即表示经过 K 总线
